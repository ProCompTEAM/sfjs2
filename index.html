Browser-native MVVM components without a build step.

SatisfactionJS loads HTML components, executes trusted component scripts, binds model properties, handles simple route-based navigation, shares data between components, and provides lightweight state/resources helpers.

Version 2.1.2.1229 No npm required HTML components MVVM bindings Client-side routing MIT License

Installation

Copy the framework file into your project and include it before your application starts.

<script src="/satisfaction.dev.js"></script>

For production, use a minified build and, ideally, a versioned path.

<script src="/versions/2.1.2.1229/satisfaction.min.js"></script>
SatisfactionJS is browser-only. It exposes global sf_* functions and does not use ES modules.

Quick start

This is the smallest routed app shell: routes, navigation buttons, a navigation switch, and two component templates.

<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>SatisfactionJS App</title>
  <script src="/satisfaction.dev.js"></script>
</head>
<body onload="sf_initialize()" allow-routing>
  <route path="/" navigation-component-name="home"></route>
  <route path="/about" navigation-component-name="about"></route>

  <nav>
    <button navigation-component-name="home">Home</button>
    <button navigation-component-name="about">About</button>
  </nav>

  <main navigation-switch>
    <component name="home" src="/views/home.html" default></component>
    <component name="about" src="/views/about.html"></component>
  </main>
</body>
</html>

Example component file

/views/home.html

<script>
component.setModel({
  title: "Home",
  count: 0,
  increment: function () {
    this.count.value++;
  }
}, "home-model");
</script>

<section template="home-model">
  <h1>{{title}}</h1>
  <p>Count: <span>{{count}}</span></p>
  <button command="{{increment}}">Increment</button>
</section>

Initialization

Call sf_initialize() when the page is ready. The simplest way is to use body.onload.

<body onload="sf_initialize()" allow-routing>
  ...
</body>

allow-routing enables route lookup and popstate handling. Without it, default components still load, but routes are not used.

You may pass a setup callback. It runs before resources and default components are loaded.

<body onload="sf_initialize(function () {
  sf_active_navigation_allowed = true;
  sf_dependency_stable_version = "2.1.2.1229";
})" allow-routing>

Components

A component is declared with the custom <component> element. Its HTML is loaded from src using XHR and inserted into the component element.

<component name="profile" src="/views/profile.html"></component>
AttributeMeaning
nameComponent name used by loaders, navigation, and component-scoped state.
srcURL of the HTML template.
defaultLoads automatically during initialization or when a parent component is loaded.
onJavaScript condition evaluated with eval. The component loads when the condition is true.
lazyBeta observer behavior after the component has been loaded.
frozenFreezes the element size while unloading and unfreezes after loading.

Anonymous default components

If a default or conditional component has no name, the framework assigns one based on the source filename and the element XPath hash.

<component src="/views/banner.html" default></component>

Manual mounting

sf_component_mount(containerElement, componentName, sourcePath) creates and appends a component element and attaches a load() method.

const host = document.querySelector("#slot");
const dialog = sf_component_mount(host, "dialog", "/views/dialog.html");
dialog.load();

Routing and navigation

Routing maps a browser path to a component name. It is active only when body has allow-routing.

<route path="/" navigation-component-name="home"></route>
<route path="/settings" navigation-component-name="settings"></route>

Any element with navigation-component-name becomes a click navigation trigger after components are set up.

<button navigation-component-name="settings">Settings</button>

Use navigation-switch when sibling components represent mutually exclusive screens.

<main navigation-switch>
  <component name="home" src="/views/home.html" default></component>
  <component name="settings" src="/views/settings.html"></component>
</main>

Active links

Set sf_active_navigation_allowed = true to intercept internal links with the active attribute.

<script>sf_active_navigation_allowed = true;</script>
<a active href="/settings">Settings</a>
Only links starting with / are handled. Links with target other than _self are ignored.

MVVM models

Models are plain objects applied to elements with a matching template attribute.

component.setModel({
  name: "User",
  message: "Hello",
  send: function (eventInfo) {
    console.log(this.name.value, this.message.value);
  }
}, "message-form");

Every non-function field is converted into a property object. After the model is set, use .value, .get(), or .set(value).

this.name.value = "New name";
this.message.set("Updated");
const current = this.message.get();

Text and attributes

<h1>{{name}}</h1>
<input value="{{name}}" bind="{{name}}" bindEvent="input">
Current version rule: keep one model property per text node or attribute. Split combined text into separate spans to avoid stale placeholders.
<p>Count: <span>{{count}}</span> / User: <span>{{name}}</span></p>

Visibility

<p visible="{{isReady}}">Ready</p>
<p invisible="{{isLoading}}">Not loading</p>
<p when="{{count}} > 3">Count is greater than three</p>
<p visible="{{isReady}}" transparent>Hidden with visibility, not display</p>

Commands

<button command="{{save}}">Save</button>
<input command="{{search}}" commandEvent="input">

The default command event is click. Commands receive an info object.

save: function (eventInfo) {
  console.log(eventInfo.element);
  console.log(eventInfo.commandEvent);
  console.log(eventInfo.model);
}

Bindings

The default binding event is change. Use bindEvent="input" for live typing.

<input value="{{email}}" bind="{{email}}" bindEvent="input">

Construct hook

A model function named construct runs after properties, commands, and bindings are connected.

component.setModel({
  title: "Hello",
  construct: function (targetElement) {
    console.log("Model is ready", targetElement);
  }
}, "view");

Template multiplication

Use component.setMultiplier(array, templateName, display) to clone a template for every model object in an array.

<script>
const messages = [
  { sender: "Anna", text: "Hello" },
  { sender: "Mark", text: "Hi" }
];
component.setMultiplier(messages, "message-item");
</script>

<div>
  <article template="message-item">
    <strong>{{sender}}</strong>
    <p>{{text}}</p>
    <button command="{{unset}}">Remove</button>
  </article>
</div>

Data exchange with points

A point is a small publish/subscribe object with subscribe, unsubscribe, and share.

const point = sf_point_set("messages");

point.subscribe("message-list", function (message) {
  console.log(message);
});

point.share({ text: "Hello" });

const samePoint = sf_point_get("messages");

Data can also be passed into a component through inputData.

component.find("message-list").load(true, point);

// In the child component:
const sharedPoint = component.inputData;

State manager

State is stored in memory and optionally in localStorage.

sf_state_set("token", "abc", true);
const token = sf_state_get("token");
sf_state_unset("token");

Component-scoped helpers automatically prefix the key with the component name.

component.setState("tab", "profile", true);
const tab = component.state("tab");
// internal key: component.<componentName>.tab
localStorage values are strings. Serialize objects manually with JSON.stringify and parse them with JSON.parse.

Resources

Resources are JSON dictionaries loaded before default components. Placeholders are replaced in component HTML before it is inserted.

<resource name="App" src="/resources/en.json"></resource>
{
  "Home.Title": "Home",
  "Home.Subtitle": "Welcome"
}
<h1>##Resource.App.Home.Title##</h1>
Dots in resource keys are literal key names. Home.Title means a JSON key named Home.Title, not a nested object lookup.

Conditional resources

<resource name="App" src="/resources/lt.json" on="navigator.language.startsWith('lt')"></resource>

Resource settings

sf_resource_undefined_key_value = "";
sf_resource_callback_after = function () {
  console.log("Resources and default components are ready");
};

Dependencies

sf_dependency_set(source, cacheAllowed) appends JavaScript or CSS to the document head.

sf_dependency_set("/lib/app.js", false);
sf_dependency_set("/styles/app.css", true);

When cache is not allowed, a version-timestamp query parameter is added.

sf_dependency_stable_version = "2.1.2.1229";
sf_dependency_set("/lib/app.js", false);
This function does not return a Promise and does not wait for scripts to finish loading. Use a Promise-based loader if application startup must block on dependencies.

Component styles

Non-global component styles are scoped by rewriting class selectors with a random postfix and applying the matching postfix classes to elements inside the component.

<style>
.card { padding: 16px; }
</style>

<div class="card">Content</div>

Use global to skip this rewriting.

<style global>
body { margin: 0; }
</style>
Scoping is class-selector based. Keep component CSS simple and test complex selectors carefully.

Security and current-version limitations

  • Use trusted component HTML only. Component scripts are executed with new Function.
  • on and when expressions are evaluated as JavaScript.
  • A strict Content Security Policy may block this execution model.
  • Components and resources are loaded with XHR; use HTTP(S), not file://.
  • Cross-origin component/resource files require CORS headers from the server.
  • Multiple different {{property}} placeholders in the same text node or attribute are not reliable in this version.
  • The dependency helper appends scripts/styles but does not wait for them.
  • localStorage state values are strings.
  • sfrender is dispatched immediately only when there are no images or all images are already complete at the check time.
  • Keep component names unique when routing and using navigation-switch.

Production checklist

  • Use a minified production file, for example satisfaction.min.js.
  • Publish builds under a versioned path, for example /versions/2.1.2.1229/satisfaction.min.js.
  • Serve JavaScript with the correct MIME type.
  • Set CORS deliberately. Access-Control-Allow-Origin: * is acceptable only for public static framework files.
  • Make sure routed paths return the same app shell on the server.
  • Keep component templates, resource JSON, and dependency paths reachable from the deployed origin.
  • Test direct page refreshes on every route.
